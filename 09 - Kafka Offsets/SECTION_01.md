# Chapter 09 - Kafka Offsets

## 📌 Overview

In the previous chapter, we learned how Kafka uses **Message Keys** to determine the destination partition for a message and how message ordering is preserved within a partition.

However, an important question still remains:

> **How does Kafka know which messages have already been consumed and which ones are still pending?**

This is where **Kafka Offsets** come into the picture.

An **Offset** is a unique sequential number assigned to every message inside a partition. Kafka uses Offsets to track the reading progress of every Consumer Group.

Offsets are one of Kafka's most important features because they enable:

- Reliable message processing
- Consumer recovery after failures
- Message replay
- Fault tolerance
- Scalable consumer applications

Without Offsets, Kafka Consumers would have no way to know where to continue reading after a restart.

Understanding Offsets is essential before learning advanced Kafka concepts such as:

- Consumer Rebalancing
- Retry Mechanisms
- Dead Letter Topics (DLT)
- Kafka Streams
- Exactly Once Processing

# ❓ The Problem Without Offsets

Suppose a Producer sends five messages.

```
Order Created

↓

Payment Success

↓

Inventory Updated

↓

Packed

↓

Delivered
```

Now imagine a Consumer starts reading these messages.

```
Consumer

↓

Order Created

↓

Payment Success
```

Suddenly,

```
Application Crashes
```

After restarting,

how should Kafka know

- Which messages were already processed?
- Which messages are still pending?
- From which message should the Consumer continue?

Without a tracking mechanism,

Kafka would have only two options:

Option 1

Start from the beginning every time.

```
Order Created

↓

Payment Success

↓

Inventory Updated

↓

Packed

↓

Delivered
```

This would cause duplicate processing.

OR

Option 2

Start from the newest message.

This would cause data loss because older messages would never be processed.

Kafka solves this problem using **Offsets**.

---

# 📚 What is an Offset?

An **Offset** is a unique sequential number assigned to every message **within a partition**.

Think of an Offset as the position of a message inside that partition.

Example

```
Partition-0

Offset 0

↓

Order Created
```

```
Offset 1

↓

Payment Success
```

```
Offset 2

↓

Inventory Updated
```

```
Offset 3

↓

Packed
```

```
Offset 4

↓

Delivered
```

Notice that:

- Every message has a unique Offset.
- Offsets always increase.
- Offsets are never reused.
- Offsets are local to a partition.

---

# 🧠 Important Points

Offsets are:

✅ Sequential

```
0

↓

1

↓

2

↓

3

↓

4
```

✅ Immutable

Once assigned,

an Offset never changes.

✅ Partition Specific

Partition-0

```
0

1

2

3
```

Partition-1

```
0

1

2

3
```

Both partitions can have Offset **0** because Offsets are maintained independently for each partition.

---

# ❓ Why are Offsets Needed?

Offsets solve several critical problems.

## 1. Resume Processing

Consumer reads

```
Offset 0

↓

Offset 1

↓

Offset 2
```

Consumer crashes.

After restarting,

Kafka resumes from

```
Offset 3
```

instead of reading everything again.

---

## 2. Fault Tolerance

If a Consumer crashes,

Kafka does not lose its reading progress.

It continues from the last committed Offset.

---

## 3. Message Replay

Sometimes developers need to process old data again.

Example

```
Bug Fixed

↓

Replay Messages
```

Offsets make replay possible.

---

## 4. Independent Consumers

Different Consumer Groups maintain different Offsets.

Example

```
Order Service

Offset

250
```

```
Analytics Service

Offset

145
```

Both Consumers are reading the same Topic,

but each maintains its own progress.

---

# 📊 Offset vs Message ID

Many beginners confuse these two concepts.

They are completely different.

| Offset | Message ID |
|---------|------------|
| Generated by Kafka | Generated by Application |
| Unique within a Partition | Business Identifier |
| Sequential | Can be Random |
| Used by Kafka Consumers | Used by Business Logic |

Example

```
Message ID

ORD-1001
```

```
Offset

25
```

Kafka cares about

```
Offset 25
```

Your application cares about

```
ORD-1001
```

These serve different purposes.

---

# 📦 Offset vs Partition

Another common confusion.

Partition

```
Storage Unit
```

Offset

```
Position inside that Storage Unit
```

Example

```
Topic

Orders
```

```
Partition-0

Offset 0

Offset 1

Offset 2
```

```
Partition-1

Offset 0

Offset 1

Offset 2
```

Offsets restart from **0** for every partition.

# 🏗 Topic → Partition → Offset Architecture

```
                    Kafka Topic
                         │
        ┌────────────────┴────────────────┐
        │                                 │
        ▼                                 ▼
   Partition-0                      Partition-1

 Offset 0 → Order-101          Offset 0 → Order-201

 Offset 1 → Order-102          Offset 1 → Order-202

 Offset 2 → Order-103          Offset 2 → Order-203

 Offset 3 → Order-104          Offset 3 → Order-204
```

Notice carefully:

Offsets are not global.

Each Partition maintains its own Offset sequence.

---

# 🔄 Offset Lifecycle

Every message follows this lifecycle.

Step 1

Producer sends a message.

↓

Step 2

Kafka stores the message inside a Partition.

↓

Step 3

Kafka assigns the next available Offset.

↓

Step 4

Consumer reads the message.

↓

Step 5

Consumer commits the Offset.

↓

Step 6

Kafka remembers the Consumer's progress.

---

# 🧾 Example

Producer sends

```
Order Created
```

Kafka stores

```
Partition-1

Offset 15
```

Consumer processes

```
Offset 15
```

Kafka records

```
Committed Offset = 15
```

When the Consumer restarts,

Kafka resumes from

```
Offset 16
```

instead of starting from Offset 0.

---

# 💡 Key Takeaways

- Every Kafka message has an Offset.
- Offsets are assigned separately for each Partition.
- Offsets always increase sequentially.
- Kafka uses Offsets to remember Consumer progress.
- Offsets enable fault tolerance and message replay.
- Different Consumer Groups maintain independent Offsets.
- Understanding Offsets is essential before learning Offset Commits, Consumer Rebalancing, and Delivery Guarantees.
